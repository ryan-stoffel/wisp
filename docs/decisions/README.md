# Decision records

A decision that affects more than one issue gets a record here. Records supersede `docs/PLAN.md` where they differ.

| [0012](0012-account-routing.md) | `AccountChoice` names a subscription by its backend or a key account by id; per-role defaults live in a `role_defaults` store table; a backend serves both credential kinds for its provider, so fallback never switches backends |
| [0013](0013-worker-sandbox.md) | Workers run in their vendor's own OS sandbox: they write only their worktree, the shared context folder, and temp; their commands can't read a denylist of credential stores but do have network access; plxd commits. Claude workers use `--restricted` with Claude Code's Bash sandbox |
| [0014](0014-agent-runs.md) | The `agents` capability is `agent/start`, `send`, `cancel`, `list`, and `events`; a run outlives its CLI processes, plxd commits it after each one, and it resumes by session after a restart; the event log is stored in SQLite; agents get no SSH session variables and a filled-in `PATH` |
| [0015](0015-subagent-chats.md) | Each agent run is a `parallax.agent` chat of its project's session; the subagents' chat agent is the default for agent-mode chat, which upstream needs to send anything; the Agents pill opens Parallax's own panel through a presenter hook in `chatDropdownPill.ts`, and shows by default |
| [0016](0016-event-log-retention.md) | The stored event log prunes host and project events by count; a run's events stay until its run row does, which nothing removes yet (#207); the in-memory replay window is also bounded by bytes |
| [0018](0018-pr-visuals-on-request.md) | `screenshots.yml` runs only for PRs with the `screenshots` label and captures only the scenes the body's `parallax-media` block names (`after`, `before-after`, `video`), into a section of the PR body instead of a comment; supersedes the every-PR rule |
| [0019](0019-coordinator-mcp-tools.md) | The coordinator's Parallax tools are `plxd mcp`, an MCP server on stdio bound to one project and one coordinator thread by arguments plxd sets; its runs carry `coordinatorThread`; Claude's coordinator allowlist is its read tools plus exactly the eight `mcp__plxd__*` tools |
| [0020](0020-drop-the-editor-fork.md) | The editor fork, its UI tests, the screenshot and release workflows, and the TypeScript generator are gone; Parallax is `plxd` only until a new frontend is decided; [0022](0022-desktop-app.md) supersedes its no-UI part |
| [0021](0021-linear-work-record.md) | The Linear project Parallax replaces GitHub issues: milestones M0 to M7 are epics with sub-issues; branches are `<type>/RYA-n-<slug>`, commits end with `(RYA-n)`, and PR bodies link the issue; blocked work gets the Blocked label and a comment mentioning Ryan |
| [0022](0022-desktop-app.md) | The desktop app is Electron, React, and TypeScript in `apps/desktop/`, built with Vite+ and pnpm and laid out like T3 Code; its main process runs `plxd attach` locally or over `ssh` and speaks 0007's JSON-RPC, the sandboxed renderer uses a typed preload bridge, and protocol types are generated into `apps/desktop/src/protocol/generated/` |
| [0023](0023-cross-platform.md) | Parallax supports macOS, Linux, and Windows, with a per-OS data folder, local transport (a socket, or a per-user named pipe on Windows), service (LaunchAgent, systemd user unit, logon task), secret store, and watcher; native Windows refuses Claude workers, which run in WSL2; PR CI tests macOS arm64, Linux x64, and Windows x64, and releases add Linux and Windows arm64 |
| [0024](0024-coordinator-chat.md) | A project's coordinator chat is a no-write run in a detached worktree of the project's repository that plxd moves to `HEAD` before each CLI process (RYA-171), started by `project/start` and driven through `agent/*`; plxd checks that worktree after every turn and stops the run on a change; a new start replaces a project's coordinator unless it is running, and the coordinator never sees its own run in its tools |
| [0025](0025-coordinator-wake-ups.md) | Runs a coordinator started wake it when they finish: summaries batch into one turn 2 s after the first, or after a turn in progress; 10 wake-ups in a row without the user pause them with `agent.wakeupsPaused`; wake-up turns carry `TurnStarted.wake`; the count and a pause are stored, and when plxd starts each coordinator gets one wake-up for the runs it started that ended after its last turn (RYA-178) |
| [0026](0026-prompt-images.md) | Images sent with a prompt or message are checked against caps sized to Anthropic's limit and 0007's frame, stored in the store's `images` table once the CLI has them, listed by id on the message's `turnStarted`, and served by `agent/image`; Claude gets base64 image blocks, Codex `--image=` temp files |
| [0027](0027-claude-permission-modes.md) | Every Claude thread offers Claude Code's permission modes (Auto, Manual, Accept Edits, Plan, Bypass Permissions); the coordinator is full Claude Code in its mode, in the project's repository, with plxd's tools allowed and no per-turn check; a subagent inherits the coordinator's current mode; a worker in Bypass Permissions runs without the worker sandbox |
| [0028](0028-release-channels.md) | `release.yml` publishes a nightly prerelease per push to `develop` and a standard Latest release per push to `main`, with generated notes, each OS attaching its files when its build is done (RYA-211); the app follows a channel by branch until an updater (RYA-68) reads the releases by prerelease flag; [0030](0030-release-versions.md) sets the tags; [0051](0051-promote-a-nightly.md) supersedes the push trigger; nightlies aren't pruned |
| [0029](0029-app-packaging.md) | The app is packaged with electron-builder: a dmg (macOS arm64), an nsis installer (Windows x64 and arm64), and an AppImage (Linux x64 and arm64), each built on its own runner with its release `plxd` in resources; `release.yml` builds them and each build attaches its files to the release as soon as it's done, `SHA256SUMS` last (RYA-211); [0030](0030-release-versions.md) replaces its versions and signs macOS |
| [0030](0030-release-versions.md) | Versions are the commit's UTC time as `YYMM.1DDHH.1MMSS` (`-nightly` on a nightly), fixed-width so GitHub's text order of same-day tags is time order, tagged `v<version>`; the app ships `app-update.yml` (github, `ryan-stoffel/parallax`) and each release attaches `latest*.yml` or `nightly*.yml`, a macOS zip, and blockmaps, with both Windows arches in one file; the macOS build is signed with the hardened runtime (`allow-jit` only) on every `release.yml` run and its dmg notarized after publishing; `plxd` reads its version from `plxd.version` beside it, so a cached `plxd` ships in any app version (RYA-211); the old `nightly-*` releases stay; [0051](0051-promote-a-nightly.md) chooses which commit is nightly |
| [0031](0031-permission-requests.md) | Claude threads in Manual, Auto, and Plan that a client starts with `approvals` (capability `approvals`) run with `--permission-prompt-tool stdio`, and plxd answers Claude Code's `can_use_tool` control requests: each is an `approvalRequested` item in `agent.output`, `agent/approve` allows, with an edited input or the request's allow rules for the session, or denies, and an `approvalResolved` item logs how it ended; a request nobody answers is denied after 30 minutes, and a cancel, a stop, or the CLI's exit resolves what waits; Codex doesn't ask |
| [0032](0032-project-names-and-icons.md) | A project's name and its optional icon (`{name, color?}`, keys of `a-z`, `0-9`, and `-` that plxd stores and never reads) live on its host; `project/update` renames it or replaces its icon without touching `updatedAt`, `project/create` takes an icon as part of its idempotency check, and a change appends a host-level `project.updated`, all behind the `projectEdit` capability |
| [0033](0033-sidebar-attention.md) | The sidebar is one list of every host's threads and Projects, most recently prompted first, with a Repos filter; each row shows Working, Needs you, Done, Failed, or its age, from `seenAt` that plxd keeps; threads snooze with a notification; `thread/update`, `repo/update`, and repo icons sit behind `threadAttention` |
| [0034](0034-threads-are-full-claude-code.md) | A thread's Claude Code run whose client answers permission requests is full Claude Code in every mode, as a coordinator's and a bypass worker's are: no worker sandbox, the user's settings, `CLAUDE.md` files, skills, plugins, hooks, and MCP servers load, its first message is the user's own, and with `approvals` it asks in Accept Edits too; a coordinator's workers keep 0013's sandbox |
| [0035](0035-codex-threads.md) | A Codex thread is full Codex on `codex app-server` with the user's own configuration: follow-ups go into the live process, a finished thread resumes by thread id, Manual, Accept Edits, Auto, and Bypass Permissions map to Codex's approval policy, sandbox, and reviewer, and its approval requests reach the app; a coordinator's Codex workers keep `codex exec` |
| [0036](0036-cursor-threads.md) | A thread can run on Cursor (backend `cursor`, threads only, subscription only) as `agent acp`: the user's `~/.cursor` loads, the first message is the user's own, follow-ups go into the live session and a finished thread resumes with `session/load`; Edit is `agent` mode, Plan `session/set_mode plan`, Bypass `--force`; permission requests and plans (as `ExitPlanMode`) reach the app, and an approved plan is built in the same turn; supersedes 0004's wait for Cursor's written OK |
| [0037](0037-accounts.md) | Parallax accounts live in Supabase Auth with no tables of our own; the main process keeps the session encrypted with `safeStorage` and gives the renderer only the profile; sign-in uses PKCE with a loopback redirect; the sidebar footer gains Profile, which opens Settings > Account (PLX-421) |
| [0038](0038-image-icons.md) | A Project's or repo's icon can carry an uploaded image (`icon.image`, 0026's `{mediaType, data}`), stored inline on the host and capped at 64 KiB of base64 (`imageTooLarge`), with 0026's checks (`invalidParams`); an icon without `image` clears it; migration 22 adds the columns, behind `iconImages { maxBytes }` |
| [0039](0039-usage-from-ccusage.md) | The Usage page's Cost and Tokens read `usage/daily`: every Claude Code and Codex session from ccusage 20 (on `PATH`, else `npx`) and Cursor's from its dashboard API with the desktop sign-in through the system `curl`, per local day, agent, and model, with a problem per failed source; ranges are Today, 7, 30, and 90 days; `usage/get` and `usage/history` stay |
| [0041](0041-thread-lineage-and-host-mcp.md) | A run's parent is the run that launched it (`runs.parent`, a coordinator's thread for its subagents), and a thread has `forkedFrom`, `title`, and `settled`, set by `thread/start` and `thread/update` behind `threadLineage`; deleting a run clears it from its children; every thread gets the host-wide `plxd mcp --thread` with nine `thread_*` tools and `pr_link`, which replace 0019's, write tools work host-wide with the sender recorded, and Claude's Task subagents are read-only children |
| [0042](0042-project-children-are-threads.md) | A Project's coordinator and children are threads on any provider, with no worker sandbox, in the Project's mode, Auto or Bypass Permissions, behind a disclaimer; New task starts a child at once from the integration branch's tip with the brief and memory index; the coordinator writes no code and runs in a worktree at that tip; threads can be made into a Project |
| [0043](0043-project-inbox-and-autonomy.md) | A Project's inbox is built from events (Needs you, Done, Failed, Decided for you, Learned); a child's `ask` never blocks; autonomy Ask me, Routine (default), or Full decides what the coordinator answers; the wake-up cap is 100 |

| [0045](0045-integration-branch.md) | Each Project lands its children one at a time on `parallax/<slug>`, squashed, after the user approves by default, running its checks; conflicts and red checks go back to the child; the user opens one PR from it |

| [0049](0049-auto-resume-usage-limits.md) | A run a usage limit stopped is `waiting` with a stored `resumeAt`: the reset Claude or Codex reported plus up to 60 s of jitter, or a backoff from 15 minutes doubling to 4 hours with no reset (Cursor); at that time plxd resumes the session with a short "continue" turn.
